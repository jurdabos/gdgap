# Principal physical columns and keys — aware variant (thesis §4.2.2)

Compact physical exhibit: the columns and keys that carry the design argument. The authoritative definitions are the DDL files under `sql/ddl/aware/` (DuckLake) and `sql/ddl/aware/innodb/` (mirror); this table lists only the principal columns, not every column.

| Structure (`lake.aware`)                                       	| Grain / role                                                                                                                                                       	| Principal columns                                                                                                                                                                                            	| Keys                                                                                                                   	|
| ---------------------------------------------------------------	| -------------------------------------------------------------------------------------------------------------------------------------------------------------------	| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------	| -----------------------------------------------------------------------------------------------------------------------	|
| `dim_sex_code`                                                 	| governed sex domain — ISO/IEC 5218:2022 core plus governed extension `U` (R1, R6)                                                                                  	| `sex_code` · `label` · `source_standard` · `is_extension`                                                                                                                                                    	| PK `sex_code`                                                                                                          	|
| `dim_gender_identity_code`                                     	| governed gender-identity domain — Stats NZ core plus extensions `U`, `NC` (R1, R6)                                                                                 	| `gender_identity_code` · `label` · `source_standard` · `is_extension`                                                                                                                                        	| PK `gender_identity_code`                                                                                              	|
| `map_nhts_sex`                                                 	| raw NHTS sex codes incl. reserves `-7`/`-8`/`-9` mapped to governed codes (R7)                                                                                     	| `nhts_code` · `sex_code` · `note`                                                                                                                                                                            	| PK `nhts_code`; refs `dim_sex_code`                                                                                    	|

Notes:

- Key declaration: the DuckLake tables are created as `CREATE TABLE … AS SELECT`, so their keys are logical; the InnoDB mirrors declare the same keys as `PRIMARY KEY` constraints. Foreign-key references are logical on both backends — referential integrity is verified by the executable R13 contract (`DATA_QUALITY_SPEC.json` rules), not by declared constraints.
- Facts carry no dimension-version key; reporting is by current recorded identity via natural key plus `is_current` (ADR-0005).
- The blind variant (`lake.blind`) holds `fact_person` and `fact_trip` with identical grains and keys and none of the sex/gender structures — the measured R2 contrast.
