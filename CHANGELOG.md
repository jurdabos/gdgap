## [Unreleased]

### Added

- `compose.yaml` plus `docs/adr/0008-containerized-mysql-foil.md`: the InnoDB foil's MySQL server is now a compose-managed container inside WSL — image pinned `mysql:8.4.11` (current 8.4 LTS patch, deliberately superseding the Windows host's 8.0.x), loopback-only `127.0.0.1:3307`, authenticated healthcheck, datadir in the named volume `gdgap_mysql_data` (ext4-native; never a `/mnt/*` bind mount, which would poison timing evidence). The root password rides `GDGAP_MYSQL_ROOT_PASSWORD` in `.env` via compose interpolation; `.env.example` updated accordingly. Supersedes the windows-host endpoint-resolver design — the portproxy/firewall runbook, `wslinfo` detection, and NAT-gateway resolution are all obsolete because WSL networking mode no longer matters.
- `gdgap mysql-doctor [--json]` (`src/gdgap/cli.py`; `diagnose()` in `src/gdgap/bench/backends/innodb.py`): sanitized connectivity diagnostics — configured endpoint, TCP reachability, authentication, server version — never printing username, password, or the full URL (failures reduce to error class plus MySQL error code); exits non-zero on failure for runbook/CI use. Covered by `tests/unit/test_mysql_doctor.py` without a live server.
- `scripts/dump_mysql.sh`: gzipped logical dump of `gdgap_blind`/`gdgap_aware` into gitignored `data/dumps/` (or `GDGAP_DUMP_DIR`, e.g. a `/mnt/d` thesis archive) for posterity and presentations; `mysqldump` reads `MYSQL_PWD` inside the container, so the password never crosses the host shell.

- Phase E benchmark harness: `gdgap bench` (new `src/gdgap/bench/run.py`, wired in `src/gdgap/cli.py`), the frozen `sql/bench/` catalogue, and `docs/adr/0004-benchmark-protocol.md`. One invocation runs one warm matrix cell (`--backend ducklake|innodb` × `--variant blind|aware`, `--repetitions` default 5, `--seed`, `--skip-storage`) over four backend-neutral queries (`q_agn_01_care_trip_share_total`, `q_agn_02_mode_share`, `q_eq_01_care_trip_share_by_sex`, `q_eq_02_ppr`) whose `{schema}` placeholder resolves to `lake.<variant>`/`gdgap_<variant>` — no duplicated per-backend texts. Protocol per ADR-0004: fresh connection, unrecorded warm-up doubling as plan capture (DuckDB json profile with profiling off during timed reps; MySQL `EXPLAIN FORMAT=JSON`; formats tagged), seed-shuffled recorded repetitions timed around execute-plus-full-fetch, normalised SHA-256 result hashes (floats/Decimals `%.9g`, sorted rows), per-query error guardrails. Evidence: append-only `results/bench/runs.csv` (full runbook §7.4 columns) and `results/bench/storage.csv`, run-keyed `results/bench/envinfo.json` (seed, engine actuals, `innodb_buffer_pool_size`, host facts), derived `results/bench/summary.csv` (median/inclusive-IQR/min/max, hash stability) regenerated from all retained raw runs, plans under `results/plans/`. `q_eq` on blind is recorded as `not_representable` without execution (capability state, not a failed timing). Storage is snapshot-aware: DuckLake active files via `__ducklake_metadata_lake` (never a Parquet glob), InnoDB `ANALYZE TABLE` + `DATA_LENGTH+INDEX_LENGTH`, with per-table, TOTAL, and `aware_minus_blind` delta rows. Cold runs stay rejected until a reset method has its own ADR. Tests: `tests/unit/test_bench_harness.py` and `tests/integration/test_bench_lake.py` (fixture smoke incl. cross-variant `q_agn` hash agreement; live InnoDB cell behind `GDGAP_MYSQL_URL`); `tests/conftest.py` now ships `sql/bench/` into the fixture root. No evidence runs were performed — authoritative numbers come from deliberate runs per the runbook.

- `docs/model/conceptual.mmd` + rendered `docs/model/conceptual.png`: the W2 conceptual model in IE/Martin crow's-foot notation (Mermaid `erDiagram`) — Household/Person/Vehicle/Trip entity sets per the FHWA codebook plus the aware-variant constructs (`SEX_CODE` list, `NHTS_SEX_MAP`, SCD-2 `PERSON_SEX` with `sex_source` provenance), grounded in `sql/ddl/aware/` (the blind baseline is the diagram minus the sex constructs, per R11). Backs the thesis 3.3 "artefacts created" claim, gives R1's evidence hook an inspectable artefact, and serves as the source for the 3.3 figure (render: `mmdc -i docs/model/conceptual.mmd -o docs/model/conceptual.png -b white -s 2`).

- `gdgap build --variant blind|aware [--backend ducklake|innodb]` (new `src/gdgap/build.py`, wired in `src/gdgap/cli.py`): the Phase D one-pipeline build. Enforces the R-number header gate before executing anything — every file under `sql/ddl/` must open with `-- R<n>[, R<n>]*:` naming IDs present in `docs/requirements.md`, else the build refuses — then executes the variant's DDL in filename order and echoes per-file R-claims plus total coverage.
- `sql/ddl/blind/` (3 files) and `sql/ddl/aware/` (6 files), all R-headered: blind = fact_person/fact_trip from the identical Parquet source minus any sex attribute, plus a total-only care-share view (the measured R2 contrast); aware = ISO/IEC 5218 code list implemented-then-extended with flagged extension rows (R1/R6), explicit NHTS reserve-code mapping (R7), SCD-2 `dim_person_sex` with `sex_source` provenance distinguishing reported/imputed/edited and `sex_code_reported` (R3/R8), facts joinable at every grain (R2), and equity views — imputation share, care-trip share by sex, PPR — with n >= 30 small-cell suppression (R9). First real build reproduces the target signal: care-trip share 10.27% (male) vs 14.89% (female), PPR 0.797 vs 1.195; blind can only say 12.66% total.
- `src/gdgap/bench/backends/` — the foil seam, both sides implemented: `ducklake.py` (canonical columnar engine, attach per `sql/00_attach.sql`) and `innodb.py` (row-oriented foil over PyMySQL; `GDGAP_MYSQL_URL` from `.env` via `load_dotenv`, friendly errors when unset/unreachable, statement splitting, batched `executemany` loads). `gdgap build --backend innodb` runs the MySQL-dialect mirrors under `sql/ddl/<variant>/innodb/` (structure-only, PRIMARY KEYs as the row-store design point, MySQL 8.0.19+) and then copies every base table from the built lake variant, so both stores hold identical warehouse content. `pymysql[rsa]` and `python-dotenv` added; `.env.example` gained a `GDGAP_MYSQL_URL` placeholder.
- Tests: `tests/unit/test_build_gate.py` (registry parsing, valid/missing/unknown headers, and a sweep asserting every shipped DDL file passes the gate) and `tests/integration/test_build_lake.py` (blind and aware builds on the fixture lake incl. provenance and suppression assertions, gate refusal mid-tree, and an InnoDB mirror test that skips without `GDGAP_MYSQL_URL`); fixture CSVs extended with the fact columns (R_AGE, WTPERFIN, trip mode/purpose/miles/weights).
- `docs/requirements.md`: the R1..R12 requirements registry — the traceability spine converting the 2.3 advocacy corpus (SAGER, UN Women/Data2X, Gebru datasheets, FAIR, D'Ignazio & Klein, Manifest-No, Venus score, ACM Code, AIRR) into engineer-inspectable requirements that 3.3 designs against, ch. 4 measures against, and 5.1 audits. Includes the traceability contract: greppable `## R<n> —` headings, the DDL header-comment convention (`-- R3: ...`) the Phase D build gate will enforce, stable-ID rules, and R3 fixed to the sex_source provenance column per the runbook's canonical example.
- `gdgap publish --maintain` plus `docs/adr/0003-cloud-mirror.md`: the flag expires non-current snapshots and deletes their files on the target after publishing (`ducklake_expire_snapshots` + `ducklake_cleanup_old_files`; MotherDuck runs no automatic DuckLake maintenance), covered by an integration test asserting a single retained snapshot; the ADR records the whole cloud-mirror arrangement — fully managed MotherDuck DuckLake `gdgap_lake` as a disposable mirror, local lake canonical, `MOTHERDUCK_TOKEN` via env only, fresh-connection verification with server-side repair, and `SNAPSHOT_RETENTION_DAYS = 7` set on the target.
- `gdgap publish [--target gdgap_lake] [--force]` (new `publish()` in `src/gdgap/ingest/nhts2017.py`, wired in `src/gdgap/cli.py`): mirrors the local lake's dataset schema into a MotherDuck-hosted DuckLake (`CREATE DATABASE ... (TYPE DUCKLAKE)`), table by table — skip when present, drop-and-republish behind `--force`, friendly error when `MOTHERDUCK_TOKEN` is unset. After every table, placement and row counts are verified on a fresh target-only connection (long-lived MotherDuck sessions once resolved a table into the wrong schema), with automatic server-side repair (CTAS + drop) when a table lands in exactly one other schema with matching counts; runs append to `results/profile/nhts2017/publish_log.csv`. Integration tests exercise the publish/skip/force cycle and the repair path against a second local DuckLake via injected connections; `_append_log` generalized to `_append_csv` for the two logs.
- `gdgap summarize` (new `summarize()` in `src/gdgap/ingest/nhts2017.py`, wired in `src/gdgap/cli.py`): renders the thesis-3.2 profile summary as `results/profile/nhts2017/profile_summary.md` — a pure formatting pass over the profiling CSVs (no lake access), with `tabulate` github tables for structure + null shares per file, the `R_SEX`/`R_SEX_IMP` code lists with codebook labels, and the sex imputation share; fails with a hint when the profile CSVs are missing. `tabulate` added as a dependency; integration tests cover the rendering and the missing-input path.
- `docs/adr/0002-dataset-scoping.md`: ADR pulling the multi-dataset decision forward — one lake schema per dataset (`lake.<dataset>.<table>`, never `main`) and one profile folder per dataset (`results/profile/<dataset>/`), while `sql/ddl/<variant>/` and the query catalogue stay keyed by the thesis's comparison axes.
- `src/gdgap/ingest/nhts2017.py` plus `gdgap ingest nhts2017 [--force]` and `gdgap profile` subcommands in `src/gdgap/cli.py`: manifest-verified (SHA-256, aborts on mismatch), idempotent ingest of the four NHTS CSVs into the DuckLake via `read_csv(..., header = true, sample_size = -1)` — skip when present, drop-and-recreate behind `--force`, row counts appended to `results/profile/ingest_log.csv`, each CREATE TABLE a DuckLake snapshot (verified: snapshots 1–4). The profiling pass emits the W1 CSVs under `results/profile/`: per-table structure (`COPY (SELECT * FROM (DESCRIBE ...))`, since `COPY (DESCRIBE ...)` is not parseable) and null shares (`COLUMNS(*)` idiom), the `R_SEX`/`R_SEX_IMP` code list, and the sex imputation share (277/264,234 = 0.1048%, defined as rows whose imputed value differs from the reported one — the codebook's `R_SEX_IMP` is the imputed companion value, not a yes/no flag; both are zero-padded VARCHAR codes in the raw CSVs).
- `tests/conftest.py`, `tests/unit/test_manifest.py`, `tests/integration/test_ingest_lake.py`: pytest coverage for manifest verification (intact/tampered/missing) and an end-to-end mini-lake ingest + profile round-trip on fixture CSVs (idempotency, force-recreate, log append, W1 outputs).
- `sql/00_attach.sql`: DuckLake bootstrap per runbook Phase C — installs the `ducklake` extension and attaches `catalog/gdgap.ducklake` (local catalog by default, per ADR-0001) with `DATA_PATH 'data/lake/'`; verified end-to-end (snapshot 0 recorded, catalog file created, both gitignored as data plane).
- `datasets/nhts2017/DATASHEET.md`: Gebru et al.-style datasheet (Motivation/Composition/Collection/Preprocessing/Uses/Distribution/Maintenance) answered for the 2017 NHTS public-use files from the FHWA User Guide and Codebook v1.2; instance counts verified against the local CSVs via DuckDB and tied to `manifest.json`/`checksums.txt`.
- `docs/adr/0001-engine-and-lake.md`: ADR recording the engine pin — DuckDB v1.5.4 at runtime, `duckdb==1.5.4` locked in `uv.lock` — plus the lake/catalog layout and the upgrade procedure.
- `.gitkeep` placeholders in `sql/ddl/blind`, `sql/ddl/aware`, `results/profile`, `results/plans`, `docs/adr`, and `tests` so the empty repo-plane directory skeleton is committable (git tracks files only, never bare directories).

### Changed

- `src/gdgap/bench/backends/innodb.py`: endpoint parsing extracted into `_endpoint()`, PyMySQL now connects with an explicit `connect_timeout` (salvaged from the resolver design), and the backend records its sanitized `host`/`port`; `src/gdgap/bench/run.py` persists them as `mysql_host`/`mysql_port` under `backend_native_settings` in `envinfo.json`, keeping container-loopback and remote-host runs distinguishable in the evidence (ADR-0008). Covered in `tests/unit/test_bench_harness.py`.
- `README.md`: containerized-MySQL quickstart (compose up, doctor, foil builds, dump export).

- R7 closed at the analytical layer (new `docs/adr/0007-response-state-granularity.md`): `dim_person_sex` now retains the reported NHTS code verbatim as `r_sex_raw` (both backends), so refusal (`-7`), don't-know (`-8`), and not-ascertained (`-9`) stay distinguishable in warehouse aggregations — previously the ISO analysis domain's single `0` merged the two ignorance kinds and the dimension carried only mapped codes, confining full granularity to the registered raw tables. Minting distinct sex codes for the ignorance kinds was rejected per the ADR-0006 labelling rule; the documented ISO-granularity merge stays in the analysis code where it belongs. R7's design hook and evidence updated in `docs/requirements.md`; `PERSON_SEX.r_sex_raw` added to `docs/model/conceptual.mmd` (PNG re-rendered, pinned mmdc 11.12.0, `-b white -s 4`); `tests/integration/test_build_lake.py` asserts the raw/mapped pairs incl. the fixture's `-7`→`U` row.
- Sex and gender identity separated into distinct governed code domains (R1 critique; new `docs/adr/0006-sex-gender-domain-separation.md`): `sql/ddl/aware/01_dim_sex_code.sql` now carries only the ISO/IEC 5218:2022 core plus `U` — a governed application extension for the nonresponse process state behind R7's refusal-vs-ignorance mapping, never an additional ISO code — and the former `X` row's concept moved to the new, separately governed `02_dim_gender_identity_code.sql` (Stats NZ-anchored `1/2/3` plus `U`/`NC` application extensions; both backends). `dim_person_sex` gained `gender_identity_code`, `NC` (not collected by source instrument) by construction, making NHTS 2017's non-collection of gender identity queryable — the gap exhibited, with the R9 analytical purpose stated in the ADR. Aware DDL renumbered `01..07` in both backend dirs to open slot 02. `docs/model/conceptual.mmd` gained the `GENDER_IDENTITY_CODE` entity, the `PERSON_SEX.gender_identity_code` attribute, and corrected `SEX_CODE` annotations (PNG re-rendered with the pinned mmdc 11.12.0, `-b white -s 4`); R1/R6 design hooks updated in `docs/requirements.md`; `tests/integration/test_build_lake.py` now asserts the two domains, the all-`NC` population, `X` absent from the sex list, and that no extension row claims an ISO source. The implemented case reads sex-aware and gender-identity-ready.
- SCD wording aligned with what is demonstrated, plus new `docs/adr/0005-scd-attribution-semantics.md`: the headers of `sql/ddl/aware/03_dim_person_sex.sql` and `sql/ddl/aware/innodb/03_dim_person_sex.sql`, the labels in `docs/model/conceptual.mmd`, and the R8 design hook in `docs/requirements.md` now say "Type-2-style (validity-interval)" instead of "SCD-2", and R8 gained a scope note: the artefact demonstrates SCD mechanics and history retention, while the analytical views deliberately report by current recorded identity (natural key + `is_current`; the facts carry no dimension-version key) — a reporting-semantics decision recorded in ADR-0005, with richer attribution semantics left as future work in general terms. Rationale: the single-snapshot case cannot exercise historical attribution, and version keys on facts would break the identical-fact-grain blind/aware contrast the experiment rests on. `docs/model/conceptual.png` re-rendered from the amended `.mmd` with `@mermaid-js/mermaid-cli` (mmdc) 11.12.0 at doubled resolution for readability (`-b white -s 4`, 3136×1584 px; previous render used `-s 2`, 1568×792 px); the render pin is now also a comment in `conceptual.mmd`.
- `src/gdgap/ingest/nhts2017.py`: `R_SEX`/`R_SEX_IMP` are now pinned VARCHAR at ingest via an explicit `read_csv` `types` override (new per-table `TYPE_OVERRIDES` + `_read_csv_options()`), so R7's verbatim survival of the zero-padded sex codes and reserve codes is a declared schema-on-write contract at the CSV→lake boundary instead of an emergent effect of the sniffer's leading-zero heuristic (fragile against engine upgrades and upstream padding changes; the aware build's string-code joins in `sql/ddl/aware/03_dim_person_sex.sql` and the summarizer's code labels depend on it). R7's design hook in `docs/requirements.md` reworded to name the override. Covered by `tests/integration/test_ingest_lake.py::test_ingest_pins_sex_codes_verbatim` (declared types + verbatim values incl. `-7`) and new `tests/unit/test_ingest_types.py` (override applies to perpub only). Lake tables are unchanged byte-for-byte — the override declares what inference already happened to produce.
- `src/gdgap/ingest/nhts2017.py`: multi-dataset-native layout per ADR-0002 — tables now live in `lake.nhts2017.<table>` (schema created idempotently at ingest), and all profiling outputs including `ingest_log.csv` moved under `results/profile/nhts2017/`; lake and catalog rebuilt from raw CSVs to apply the layout (rebuildable per ADR-0001). `tests/integration/test_ingest_lake.py` extended with a schema-placement assertion.
- `.gitignore`: re-included `sql/**/*.sql` via a negation rule so DDL scripts are committable despite the global `*.sql` ignore inherited from the skeletal template; data-plane dirs (`data/`, `catalog/`) stay ignored.
- `.gitignore`: re-included `datasets/` (negation of the template rule) so dataset metadata — `DATASHEET.md`, `manifest.json`, `checksums.txt` — is committable; bulk data files inside remain ignored via the extension rules (`*.csv`, `*.zip`, …).
- `.gitignore`: re-included `results/**/*.csv` so the profiling/bench evidence stays tracked per the runbook ("results are evidence"), despite the global `*.csv` ignore.

### Removed

- `.gitkeep` placeholders in `sql/ddl/blind` and `sql/ddl/aware`, superseded by the real DDL files.
- Root `main.py` scaffolding leftover (`src/gdgap/main.py` remains the packaged module).
- Flat `results/profile/*.csv` evidence files, superseded by the dataset-scoped `results/profile/nhts2017/` set.

### Fixed

- `tests/conftest.py` loads the root `.env` (`override=False`) before test modules evaluate their `requires_mysql` markers, so the live InnoDB tests unskip without the manual shell `export` previously required (the markers read `os.environ` at import time, before `InnodbBackend` ever calls `load_dotenv`).

- `src/gdgap/ingest/nhts2017.py`: `gdgap publish` now loads `.env` before checking `MOTHERDUCK_TOKEN` (previously only the InnoDB backend did), so the token works across sessions without re-exporting; error message updated accordingly.
- `datasets/nhts2017/manifest.json`: consolidated four concatenated JSON objects into one valid document (single `files` array with name/sha256/bytes per CSV) so `json.load`-based manifest verification works.
- `src/gdgap/cli.py`: `gdgap push` now detects commits that exist locally but not on the upstream (`git rev-list --count @{u}..HEAD`) and pushes them even when the working tree is clean; previously an aborted push left the commit stranded and re-running reported "Nothing to push". Same fix applied to the skeletal template (`~/skeletal/scripts/cli_push_template.py`) for future repos.
- `src/gdgap/cli.py`: commit messages no longer get a hardcoded `Co-Authored-By: Warp <agent@warp.dev>` trailer, in line with the ecosystem signing policy (responsibility stays with the human author); also removed from the skeletal template.
- `pyproject.toml`: added the missing `[build-system]` table (hatchling) so uv packages the project and installs the `gdgap` console script. Modern `uv init` scaffolds an unpackaged app, so uv skipped `[project.scripts]` entry-point installation and `uv run gdgap --help` failed with "Failed to spawn".
